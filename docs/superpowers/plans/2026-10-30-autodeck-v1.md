# autodeck v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local two-deck auto-DJ that turns YouTube or YouTube Music songs and playlists into one continuous, phrase-aligned mix, with genre switching.

**Architecture:** A Python engine (FastAPI) downloads songs (yt-dlp), analyzes them (beats, key, sections, genre), plans the order and transitions, and pre-renders tempo-mapped audio (Rubber Band). The UI is plain browser HTML/JS. It plays two decks through the Web Audio API and schedules each incoming deck sample-accurately against the engine's plan. The engine owns the queue and the plan; the browser owns the clock.

**Tech Stack:** Python 3.12, uv, FastAPI + uvicorn, yt-dlp, beat_this (torch), essentia (plain, not essentia-tensorflow), onnxruntime (Discogs genre model), faster-whisper (tiny, language ID), librosa, soundfile, pyrubberband + the `rubberband` CLI, pytest. Frontend: vanilla JS, Web Audio, canvas.

**Spec:** `docs/superpowers/specs/2026-10-30-autodeck-design.md`

## Global Constraints

- Runs on macOS, Apple Silicon. Local only, nothing hosted. The server binds `127.0.0.1`.
- Library cache lives in `~/autodeck-library/<youtube-id>/`, overridable with the env var `AUTODECK_LIBRARY`. Never inside the repo. `.gitignore` excludes `*.flac`, `*.wav`, `*.m4a`, `*.opus`, `cookies*`, and `.env*`.
- yt-dlp reads cookies with `cookiesfrombrowser=(AUTODECK_BROWSER or "chrome",)`. Cookies are never written to disk by us and never logged.
- `analysis.json` carries `"version": ANALYSIS_VERSION`. A song is never re-downloaded or re-analyzed when the cached version matches. The owner-set `genre` survives re-analysis.
- Spec values, all in `autodeck/config.py`: `WINDOW_SIZE = 10`, `FIXED_NEXT = 2`, `BEATMATCH_MAX_PCT = 0.08`, `EASE_BARS = 16`, `PHRASE_BARS = 8` (a boundary is any multiple of 8 bars from the first downbeat; prefer 16), and `DEFAULT_GENRES = ["Pop", "Hip-hop", "Romanian hip-hop", "Romanian sârbe"]` plus `"Any"`. The genre list can be edited and is persisted in `~/autodeck-library/genres.json`.
- Tempo changes always keep the pitch (Rubber Band). Never use `playbackRate` for tempo.
- No gaps and no train-wrecks: every transition starts on a phrase boundary of the outgoing song when it has a reliable grid.
- No secrets in the repo. Comment every non-obvious decision in code. This is the owner's rule. Use a `ponytail:` comment for deliberate shortcuts with a known ceiling.

## Review Focus

1. **A watch link that also has `list=`** (`watch?v=X&list=RD…`): a reasonable person expects only that song, not a 50-song radio mix. A `/playlist?list=` URL imports the playlist. → test in Task 3.
2. **A song that can't be downloaded** (removed, age-restricted, region-locked) in the middle of a pool: it gets marked `failed`, the window refills, and the mix keeps going. → tests in Tasks 3 and 8.
3. **The active genre runs out of ready songs:** the next pick falls back to `"Any"` with a visible notice, and it never goes silent. When everything is exhausted, the last song plays to its end. → test in Task 6.
4. **A short song** (about 60–90 s) where the intro, blend and 16-bar ease overlap: entry, exit and ease are clamped so `exit > entry + blend` and the ease ends before the exit. Nothing goes negative or out of order. → test in Task 6.
5. **The beat tracker returns double or half the real tempo** (85 reported as 170): pairing logic treats 2:1 as a half-time or double-time match rather than an impossible pair. → tests in Tasks 2 and 6.

### Shared data model (`autodeck/library.py`). Every task uses these names.

```python
ANALYSIS_VERSION = 1

@dataclass
class Section:  start: float; end: float; label: str        # "intro" | "body" | "outro"

@dataclass
class Analysis:
    version: int
    bpm: float                       # original tempo, octave as detected
    beats: list[float]               # seconds, original time
    downbeats: list[float]
    grid_reliable: bool
    key: str | None                  # e.g. "A minor"
    camelot: str | None              # e.g. "8A"
    energy: list[float]              # one value per second, normalized 0..1
    sections: list[Section]
    play_start: float                # after trimming silence or spoken intro
    play_end: float
    genre_guess: str | None
    language: str | None             # ISO code from lyric language ID, e.g. "ro"

@dataclass
class Song:
    id: str                          # YouTube video id
    title: str; channel: str; duration: float
    status: str                      # "queued"|"downloading"|"analyzing"|"ready"|"failed"
    error: str | None = None
    genre: str | None = None         # owner-set; wins over genre_guess
    genre_hint: str | None = None    # from playlist import ("import as Sârbe")
    analysis: Analysis | None = None
    def effective_genre(self) -> str | None   # genre or analysis.genre_guess or genre_hint

def song_dir(song_id: str) -> Path
def save_song(song: Song) -> None            # writes <dir>/song.json (+ analysis.json)
def load_song(song_id: str) -> Song | None   # None if missing; drops analysis if version mismatch, keeps genre
def load_pool() -> list[Song]; def save_pool(ids: list[str]) -> None   # pool.json = ordered ids
```

Audio lives at `<dir>/audio.flac`, peaks at `<dir>/peaks.json` (`list[float]`, 2000 points, max abs per bucket), and renders at `<dir>/render-<hash>.wav`.

### Task 6: Planner

**Files:** Create `autodeck/planner.py`, `tests/test_planner.py`

**Interfaces:**
- Consumes: `Song`, `Analysis`, all of `music.*`, config constants.
- Produces:

```python
@dataclass
class Transition:
    kind: str          # "blend" | "half_double" | "cut" | "echo" | "dropswap" | "fade"
    out_id: str; in_id: str
    out_at: float      # seconds, outgoing ORIGINAL time (phrase boundary when grid reliable)
    in_at: float       # seconds, incoming ORIGINAL time where its audio starts playing
    length: float      # seconds of overlap/effect (0 for cut)
    tempo_ratio: float # incoming speed during blend (1.0 unless blend/half_double)

def score_pair(a: Song, b: Song) -> float
def order(current: Song, candidates: list[Song], pinned: dict[int, str], genre: str) -> list[Song]
def pick_transition(a: Song, b: Song, after: float | None = None) -> Transition
def genre_entry(current: Song, pool: list[Song], genre: str) -> tuple[Song | None, bool]  # (song, fell_back_to_any)
```

- [ ] **Step 1: Failing tests.** Build songs with a `make_song(bpm, camelot, energy, duration, grid=True, genre=...)` helper that creates a synthetic `Analysis`.
  - `order` prefers a 124 BPM 9A song over a 150 BPM 3B song after a 122 BPM 8A song, keeps `pinned` positions, and only returns songs in `genre` (or all songs when `genre=="Any"`).
  - `pick_transition` for 122→124, both with grids: `kind=="blend"`, `out_at` is in `phrase_boundaries(a)` and inside `a`'s outro, `in_at == b.play_start`, `length` is a whole number of bars and at most the shorter of a's outro and b's intro, `tempo_ratio ≈ 122/124`.
  - 170 vs 86 → `"half_double"` (Review Focus 5).
  - 150 vs 90, both with grids → one of `cut|echo|dropswap`, `out_at` on a phrase boundary, `tempo_ratio == 1.0`. Use `dropswap` when b's first body section starts at most 32 bars in; then `in_at` = that start.
  - Either side without a grid → `"fade"`, `length` between 3 and 6 s, `out_at` at the lowest-energy second within the last 20 s before `play_end`.
  - `after=t` (mix now): `out_at == next_boundary(a.downbeats, t)`.
  - Short-song clamp (Review Focus 4): a 70 s song paired with anything gives `a.play_start < out_at <= a.play_end - length`, and `b.play_start <= in_at`.
  - `genre_entry` with no ready songs in the genre returns `(best_any, True)` (Review Focus 3). An empty pool returns `(None, True)`.
- [ ] **Step 2: FAIL → implement → PASS.**
  - `score_pair = 0.5*tempo_closeness + 0.3*camelot_score + 0.2*(1-|Δenergy|)`, where `tempo_closeness` is 1 for match, 0.8 for half_double, and 0 for none. ponytail: hand-tuned weights.
  - `order` is greedy: from `current`, repeatedly take the best-scoring remaining candidate, filling around the pinned slots.
- [ ] **Step 3: Commit** `feat: add mix planner (ordering, transitions, genre entry)`

### Task 9: Server API

### Task 10: Two-deck browser UI

**Files:** Create `web/index.html`, `web/app.js`, `web/style.css`

**Interfaces:**
- Consumes: the Task 9 API.

Layout B: Deck A | crossfader | Deck B on top, with genre buttons below, then the queue (drag to reorder, an inline genre dropdown per row, a status badge), then a drop zone and URL box ("import as genre" select). Each deck shows title, artist, genre, `bpm original → playing`, key, a canvas waveform from `peaks` with a playhead, and downbeat and section markers.

Audio graph per deck: `AudioBufferSourceNode → BiquadFilter(highpass, 20 Hz idle) → GainNode → (DelayNode feedback loop for echo) → master`.

  - `cut`: an instant gain swap at `T0`.
  - `echo`: the outgoing delay is one beat long with 0.5 feedback, fading over `length` while the incoming comes in at `T0 + length`.
  - `dropswap`: like `cut`, with the incoming offset at its drop.
  - `fade`: a linear crossfade.
